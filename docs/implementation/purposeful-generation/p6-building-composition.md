# P6: bounded buildings and a street

27 October 2026. Built on P5 `660f0a5`. This completes the bounded P3–P6 implementation goal; canonical town integration is a subsequent milestone.

`two-storey-building-v1` composes immutable framed-room plans with the retained `straight-stair-v1` recipe. The library reserves its west stair/access zone before placing storage. Five east-wall cases per storey remain usable; the unfurnished program uses the same structure without asserting a residential or service function that has not been implemented.

Each building has a 9.6-by-16 interior footprint, .16 walls, .18 slabs, two 4.8-high interior envelopes, and a flat roof with a .6 parapet. The complete envelope is 9.76 by 10.74 by 16.16, from Y=-.18 to 10.56. Floor datums are Y=0 and 4.98. The stair recipe receives rise=4.98, width=1.8, tread=.42, 18 steps and landing=1.8; it retains native treads/risers rather than inventing a second stair generator. Ascent is +Z, translated to X=-3.2 and Z=-3.78. Full decks own the lower and upper landings.

The frame chain is native local geometry → building local translation → optional building instance translation in `authoring-surface-v1` → Three scene/export coordinates. Every frame is right-handed Y-up. One world unit maps to one exported coordinate unit; this is an identity game-scale proof, not a calibrated real-world meter claim or a Blender scale qualification. No conversion from logical cells is applied twice.

The upper deck is split around a 2.2-by-7.56 shaft. Ground ceiling members are removed; joists/rafters crossing the shaft are physically cut and supported by named shaft posts, side headers and end headers. Cut members retain `sourceMemberId`, stable physical end identities and the common UV datum. Bearing validation checks both actual support containment and the member endpoint, including a negative fixture with valid but exchanged bearings. Required body-height routes turn around the existing lower landing post; .76-wide access and 2.7-high clearance are explicit. The full shaft headroom volume is free of non-flight structure.

Walls, shared slab bands, floor holes, upstairs windows and roof derive from the same envelope. Upstairs exterior door apertures gain real sills and lintel infill; only ground-floor exterior openings remain doors. The building profile pockets joists inside the outer masonry skin to avoid coincident exterior timber/masonry faces. This bounded adaptation changes neither canonical dungeon geometry nor the existing `framed-room-v1` recipe. It changes building framing cross sections only; floor spacing, openings, stairs and instance footprints retain the datums above.

`building-composition-v1` places a library and unfurnished neighbor at X=-5.68/+5.68, leaving a surfaced 1.6-wide alley. A 4.8-deep street meets both front floor thresholds at Z=8.08, Y=0. The complete composition envelope is X=[-11.6,11.6], Y=[-.18,10.56], Z=[-8.08,12.88]. Same-realm building occupancy, shared ground volumes, entrance joins and envelope containment are checked. Overlap, changed realm, changed elevation and disconnected approaches fail. An independent dungeon realm is not compared as a physical neighbor or implicitly connected to this street.

The workshop now supports building/street assemblies, exterior/eye/overhead views and a lower-storey inspection toggle. Export rebuilds the complete source regardless of cutaways. Controls are held while a bake is active so a completed preview cannot silently belong to a newly selected recipe. Full nested metadata participates in portable cache identity. Unsupported animation now rejects once without orphaned asynchronous errors.

Evidence boundaries and next work:

- **PASS:** complete local authoring, bounded same-realm composition, source preservation, portable material/texture closure, standard-loader rendering and independent structural import.
- **UNKNOWN/open:** Blender import, human visual acceptance, permanent cultural/regional art language, engineering/load/weather analysis and city-scale performance.

Existing canonical dungeon travel remains the admitted runtime surface. Authoring clearances and exported metadata grant no movement or disclosure.

Future world-data integration should preserve `ConstructionPlan.routes` as reserved clearance volumes. Semantic person/food/service relationships need their own typed graph and provenance; they are not inferred from those volumes. Versioned program constraints can feed storage/shaft/entrance reservations before geometry. Parcel occupancy requires realm identity and transformed envelopes; cross-realm links require explicit canonical capability. New mechanisms such as lifts or dumbwaiters remain unavailable until implemented and qualified. Broader village/district planning should reuse these bounded recipes and independently address road graphs, parcel programs, service access, material/style constraints, streaming and admission.

Current GLB extras retain anchors/member references but do not serialize `ConstructionPlan.routes`. Anchor kind `door` also covers stair landings; it is not a semantic entrance/service classification. A future semantic sidecar should carry typed participants and route witnesses bound to exact plan/artifact hashes, instead of reconstructing them from object names, proximity or a broad anchor kind.
